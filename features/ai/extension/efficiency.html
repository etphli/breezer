Breezer 1.2.0

Less repeated work

The changes behind the measurements, and the work still ahead.

What changed

Combined 1.2.0 candidate, not yet released. Measured on one M1 Mac against the previous Breezer and Chrome.

Most of this work removes repeated effort. It did not make the whole browser faster, and some results got worse.

Saved tabs

Matching open tabs with saved records now builds a lookup index once per operation instead of comparing every pair. The sidebar model also indexes saved entries.

This measures JavaScript work on stored records, not 1,000 live tabs or overall browser speed.

Less idle work

Sidebar rows keep their elements when nothing visible changed, so keyboard focus stays put.

Organato’s helper starts on first request, is shared between pages and exits when idle. The updater helper is also released when idle, and AI provider code loads only when needed.

Built-in filter lists can load from checked, prepared copies, with the normal compiler as fallback. The build also used Chromium’s Apple Silicon profile-guided optimization (PGO).

None of these was measured alone in the browser comparison, so none gets individual credit.

The first-load pause is shorter. Chrome is still faster. New tabs and reopening a profile retain a lead over Chrome that the previous Breezer already had.

Navigation and memory regressed. Typical local navigation is slower, and ten-tab RSS is higher than both comparators. With one tab, RSS matched Chrome but exceeded the previous Breezer.

The macOS memory footprint barely moved. CPU readings were too small to measure reliably, so there is no CPU or battery claim.

Still to do

Next: find the causes of the navigation and memory regressions, trace the remaining first-load pause and get a valid Chrome footprint. Feature acceptance and the signed release build are also unfinished.

How these numbers were measured

Browser test

Medians from six balanced rounds on one Apple M1 Mac on AC power, with 36 scored launches.

Startup uses initialized or reused profiles, not a cold boot. Navigation uses a local test page, not general websites. Six rounds show medians and ranges, not statistical significance.

Memory
RSS adds up each process’s resident memory and can count shared pages more than once. Chrome’s macOS footprint is unavailable because some of its samples failed identity checks.
Saved-tab test
A separate synthetic test: six alternating rounds comparing the previous and new saved-tab code.
Candidate build
A private, ad hoc signed build whose app metadata still reads 0.20.1.1. Full feature checks and the release build are pending.
